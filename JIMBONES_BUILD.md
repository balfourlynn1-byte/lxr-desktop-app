# JIMBONES No Clip + Metallic/Wavetable — v1.7.93
This build contains no Step FX engine/page. Each voice defaults to Mode 0 (original only); Mode 1 adds Metallic, 2 Wavetable, 3 both. Original synthesis remains under both layers. On the selected voice press OSC once for its original oscillator page, again for the added layer pages. The first added page shows the four macros (Met/Noi/Agg/Tex). Continue pressing OSC through velocity, FM, noise, drive and wavetable pages until `Mod`, `FML`, `WTL`, `Dec` appears. Set Mod to 1/2/3, then independent FML/WTL amounts. Repeated OSC accesses added macro/deeper controls; encoder selects the deeper parameter and knob edits it. Original menus stay accessible via their buttons.

Four macro controls: METAL, NOISE, AGGRESSION, TEXTURE. Velocity modulation amounts are centred at 64 (neutral), with 0 negative and 127 positive. Twenty-eight parameters per voice include mode, both levels, decay, all four macros and velocity amounts, pitch, FM ratio/depth/feedback, detune, noise level/colour/transient, drive/saturation/bits/velocity sensitivity, wavetable position/movement/randomisation/pitch envelope. Kits and temporary autosave carry a versioned checksummed extension; old/missing/corrupt extension defaults layers OFF. The original parameter payload stays at its legacy offset. New layers do not morph between kits in this version.

Texture now produces stronger FM evolution and reflected wavetable scanning, plus pitch instability. At full Noise with neutral Colour 64, the added metallic layer crossfades to unpitched white-like noise; lower Colour darkens it, higher Colour removes low frequencies. Original voice audio remains underneath. Aggression shapes drive/clipping/bit reduction independently of FM ratios and depth.

The prior layer retrigger added its previous output on top of a fresh oscillator attack. This revision computes a correction from the previous sample to the new attack instead. In the isolated regression, the largest retrigger boundary jump is zero (all six voices/modes). This correction affects only new layers; the recovered original 132-sample smoother remains unchanged. Coefficients are hoisted out of the sample loop and unused wavetable/noise work is skipped.

Tests: `sh tests/run_host.sh` and `sh tests/retrigger/run_tests_mac.sh`; shared production DSP suite in `tests/production`. Mode 0 matches the No Clip host render bit-for-bit. Six-voice rapid MIDI destination/pitch/velocity switches, open/closed hats, and all enabled modes render deterministically. The maximum-fader mix still saturates (the baseline also saturates); use independent layer levels and mix headroom. These results do not prove the FD-8/Ableton hardware crunch is fixed, nor do they measure physical CPU deadlines. Test that setup before stage use.

## Foundation and build
Independent branch from recovered No Clip commit df39d7f. That source built byte-for-byte to the user's working v1.7.90: SHA-256 `57ce6e6a6ad729d4e7a4c1d657fce10e39c0c94f94a24abc078442afe74b266c`. The recovered 132-sample smoother and its integration remain in the three original drum voices. Original snare/cymbal/hat algorithms are retained.

Build with ARM GNU 16.1.0, CMake and Ninja: `cmake --preset release -DCMAKE_C_FLAGS=-fstack-usage`, then `cmake --build --preset release`. Existing desktop updater container, no bootloader changes. `python3 tests/validate_image.py build/release/LXR_V2_V1.7.93.img --binary build/release/LXR_V2_STM32F765.bin` verifies header, checksum, payload and vectors. Native tests do not replace physical testing. Debugger variables `jb_audioLastCycles`, `jb_audioMaxCycles`, `jb_audioOverruns` measure render duration; they exclude MIDI/other ISR work and need on-device observation. Emulated counters are disabled.

Back up the SD card and keep the original No Clip image off-card. Place only the chosen update image in the SD root (move other updater images off-card), power off, insert card, hold the encoder while powering on, wait for LXR Updater and Update OK. Never interrupt flashing. Restore v1.7.90 the same way to roll back. Test independently before live use.
